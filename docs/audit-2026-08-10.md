# Chork full audit — 2026-08-10

A read-only audit of the whole app + schema, run to choose a **direction**, not
to change code. Framing: **make it robust without breaking anything first**,
then tighten features / user journeys. Nothing in this pass was modified.

data-access/correctness, UX/journeys, code-quality/dead-code) + direct live-DB

## Live-verified corrections (read first)

- **The `jam_summary_players` deletion bomb is LIVE**, not fixed. Migration 044
  restructured the PK (surrogate `id` + partial unique) intending to fix it, but
  **omitted `ALTER COLUMN user_id DROP NOT NULL`**. Dropping a PK does not clear
  the column's NOT NULL flag, so `user_id` is still `NOT NULL` + `ON DELETE SET
  NULL` → `23502`. **Reproduced during the account wipe this session.** One-line
  fix. (The schema lane read 044 and believed it fixed — only the live check /
  actual failure caught it.)
- **Sentry IS wired** (`sentry.{client,server,edge}.config.ts` exist, hooked into
  `next.config.ts`), despite `roadmap.md` still listing it as a TODO. The gap is
  that `read.ts` failures log via `logger.warn` → stdout, not the error bucket,
  so they never reach Sentry.
- **`follows`/`follower_count` cleanup is complete** — zero stale references
  (clean bill of health, contra the CLAUDE.md warning to watch for them).

## Direction G — Finish half-built journeys / wire up dead UI
*FEATURE work — the "tighten features/user journeys" bucket for AFTER robustness. Several are advertised in the product's own copy. Backends (incl. tests) often already exist.*

- **Jam:** the tested `set-players` realtime action is **never dispatched** → live-player sync silently broken (highest-severity UX bug); no UI to leave a jam (server ready); ending gives no signal to other open sessions; leaderboard hard-caps at 5/20; offline queue only retries `TypeError` → silent data loss; add/edit/end have no offline + no `try/catch`.
- **Admin:** invite-a-second-admin has no UI (built + tested); multi-gym/multi-admin unbuilt but advertised ("Enterprise: multi-gym chains"); cross-gym competition linking has no UI path; zero-route sets can go live; cron auto-publish bypasses the climber `announce()`.
- **Crew:** "Create a new crew" button is a verified no-op; creators have no Leave/delete affordance (incl. solo-owner, which the backend supports); blocked-creator message points at a non-existent "remove member" feature; "shares a crew" invite-block is global, not per-crew; no way to see/cancel outbound invites.
- **Competition:** no entry point anywhere — zero links to `/competitions/[id]`, no browse list, no nav item (discovery, not build quality).
- **Profile / the finished-set state:** gymless own-profile is blank with no CTA; **the original ask** — the "No active set" bare one-liner + auto-archive-on-`ends_at` lifecycle — lives here (design already drafted this session).

1. `jam_summary_players.user_id` DROP NOT NULL — kills the deletion bomb (A, C-sev).

5. `compute_points` `search_path=''`; drop `is_blocking()`; add 3 FK indexes (A/B).
6. Delete the ~15 dead exports + orphan asset (F).
